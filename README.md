# StayChat - Hotel Booking Conversation Agent

A hotel booking conversational agent built with LangChain, LangGraph, Gemini 3.6 Flash, and a deterministic room matching and pricing engine.

## 1. How to Run

From a clean clone, the project can be set up and run in 3 commands:

```bash
git clone <YOUR_REPO_URL> && cd staychat-bot
pip install -r requirements.txt
python test_scenarios.py

Before running, create a .env file in the project root containing:

GEMINI_API_KEY=your-gemini-api-key

The test command runs all six end-to-end scenarios and generates transcripts.md.

2. Architecture
Gemini 3.6 Flash handles natural-language understanding and extracts booking information from user messages.
LangChain provides the LLM interface and structured output using the ExtractedDelta schema.
LangGraph manages the conversation workflow between NLU extraction and business logic.
The LLM handles English/Hinglish understanding, date interpretation, guest counts, room requirements, preferences, and out-of-scope requests.
Deterministic Python code handles conversation state updates, room combinations, capacity checks, child policies, and pricing.
InventoryMatcher performs room allocation and all pricing calculations using the hotel's inventory.json.
The boundary is intentional because pricing, capacity, and inventory decisions should not depend on probabilistic LLM output.
This keeps booking calculations reproducible and prevents incorrect prices or unavailable room configurations from being generated by the LLM.
3. Conversation State

Conversation state is stored using ConversationGraphState and tracked using a session_id.

Each user message is processed as a delta containing only the information extracted from that message.

Existing state is preserved when a field is not mentioned. When the user changes a preference, such as AC to Non-AC, only that specific field is updated while dates and guest information remain intact.

The system asks follow-up questions only when required information is missing. Once sufficient information is available, the deterministic matcher generates room recommendations.

4. Six Test Transcripts

The project contains six end-to-end test scenarios:

Vague initial inquiry — verifies that missing booking information is requested.
Complete direct booking — verifies that a complete request requires zero unnecessary follow-ups.
Hinglish slot extraction — tests phrases such as kal, log, bacche, and bina AC.
Changing preferences mid-conversation — verifies that preferences can be changed without losing existing state.
Multi-guest & child policy handling — tests occupancy and child-related booking rules.
Mid-flow out-of-scope amenity interruption — verifies that unrelated requests are handled without losing the booking context.

Run:

python test_scenarios.py

6. Honest Note / Limitations
The current session state is stored in memory, so it is not persistent across application restarts.
The project uses the Gemini API, so natural-language extraction depends on API availability and quota.
The current matcher intentionally limits room-combination generation to a maximum of 3 rooms to keep computation bounded.
Production PMS integration and external messaging-channel integration are not implemented in this technical task.
The Gemini AFC warning may appear during execution, but it does not affect the test results or booking logic.
